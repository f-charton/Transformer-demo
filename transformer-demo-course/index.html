01

Letters in, a number out

What Transformer-demo does, and what happens between pressing "run" and getting a trained model.

The whole project in one picture

The project teaches a transformer one task, called amplitude. The input is a word made of the letters a to f. The output is a whole number.

1

ceeceabaecdd
a word of letters

→
2

The model reads it

→
3

-1216
its integer

Nobody writes a rule for turning the word into the number. The model has to find the pattern by looking at examples.

Think of it as a deck of flashcards

Each line in a data file is one flashcard: the word on the front, the number on the back. These are real lines from the files in data/.

Why some cards are held back

A student who has memorised the deck can still fail on a new card. Checking the model on cards it never studied is the only way to know whether it learned the pattern. Engineers call the studied cards the training set and the held-back cards the validation and test sets.

How you start a run

The usual way in is the notebook notebooks/Base.ipynb. One cell lists the settings you want to change; everything else keeps its default.

These settings are called hyperparameters. On the command line, each one is a flag such as --max_epoch 1.

What happens after you press run

The notebook hands those settings to one function, train.main(params). That function runs the same five stages every time.

1
Open an experiment folder

A new folder is created and the settings are written into it, so every run leaves a record.

2
Build the pieces

The task rules, the model, the trainer and the evaluator are created, in that order.

3
Train

The model answers small groups of cards, gets corrected, and adjusts itself. This repeats until the epoch is full.

4
Evaluate

The model answers the held-back cards with no corrections, and its score is logged.

5
Save, then repeat

The model is saved to disk. Stages 3 to 5 repeat until max_epoch is reached.

Meet the cast

Six pieces of code do all the work. Knowing who does what tells you where any change belongs.

A sports club, not one big program

The code is organised like a small sports club. Each role has one job, and the manager only decides who goes next.

📋
train.py: the club manager

Reads the settings, hires everyone, then calls "train" and "evaluate" in turn.

📖
Environment: the rulebook

Knows the task: which symbols exist, how to write an answer, how to judge one.

🧺
EnvDataset: the kit manager

Hands out the drills: reads cards from a file and packs them into small groups.

🏃
Model: the athlete

The transformer. It is the only piece that actually learns.

📣
Trainer: the coach

Runs each practice step, corrects the athlete, and keeps the save files.

⚖️
Evaluator: the referee

Sets the exam on held-back cards and reports the scores. Never corrects the athlete.

03

From letters to numbers

A model can only do arithmetic. Follow one line of the data file as it is turned into something the model can read.

The codebook

A telegraph operator cannot send the word "storm". They look each letter up in a codebook and send the code. The receiver uses the same codebook to turn it back.

The project does the same thing in two steps. First it cuts the text into pieces called tokens. Then it replaces each token with its line number in a list called the vocabulary.

1

Raw text
abbabfafbd  -16

→
2

Tokens
a b b a … INT- 16

→
3

ID numbers
1006 1007 … 1005 72

How an integer becomes tokens

The letters are easy: one letter, one token. The answer needs a decision. The code writes the sign as its own token, then cuts the digits into chunks using a number base of 1000.

CODE · src/envs/tokenizers/integer.py 
    def encode(self, value):        value = int(value)        base = self.base        neg = value < 0        value = -value if neg else value        res = []        while True:            rem = value % base            value = value // base            res.append(str(rem))            if value == 0:                break        tag = "INT-" if neg else "INT+"        return [tag] + res[::-1]
PLAIN ENGLISH

A recipe named "encode" that takes one number.

Make sure it is a whole number.

Look up the base (1000 by default).

Remember whether the number is negative, then drop the minus sign.

Start an empty list of chunks.

Repeat: peel off the last three digits (the remainder after dividing by 1000) and keep what is left.

Store the chunk as text.

Stop once nothing is left.

Pick the sign token.

Hand back the sign followed by the chunks, biggest first.

288 becomes INT+ 288 (two tokens)
-16 becomes INT- 16 (two tokens)
-1216 becomes INT- 1 216 (three tokens)

Building the vocabulary

When the Environment is created, it collects every token the task could ever use and numbers them. This list is fixed before training starts.

The chunks 0 to 999, plus INT+ and INT-.

Why batches need padding

The model processes a batch as a rectangular grid, so every row must have the same length. Answers have different lengths, so shorter rows are filled with <pad>.

<eos> <ans> INT- 1 216 <eos> The answer -1216, six positions
<eos> <ans> INT+ 288 <eos> <pad> The answer 288, one filler added to match

Notice that <eos> appears at both ends. This code uses the same token to mark the start and the end of a sequence.

🧭
Padding must not count

Filler positions carry no information, so the model must be neither rewarded nor punished for them. Module 4 shows the one line that tells the scoring to ignore the pad ID. Forgetting this is a classic bug in sequence models.

04

The model and one learning step

What is inside the transformer, how it is told it was wrong, and which settings change its size.

A mixing desk with 2.8 million sliders

Picture a sound engineer at a mixing desk. The sound that comes out depends entirely on where the sliders sit. Training is the engineer listening, then nudging every slider a tiny amount towards a better sound.

The model's sliders are called parameters. The shipped run logs Number of parameters: 2856000.

👓

Encoder: the reader

Reads all the letters of the word at once and produces a set of internal notes about it.

✍️

Decoder: the writer

Writes the answer one token at a time, consulting the reader's notes before each token.

This two-part design is the default, encoder_decoder. The --architecture flag also accepts encoder_only and decoder_only.

What one layer does

The reader and the writer are each a stack of identical layers. Every layer runs the same short routine.

1
Self-attention: look at your neighbours

Each position looks at every other position in its own sequence and decides which ones matter for it.

2
Cross-attention: look at the reader's notes

Writer layers only. Each answer position looks back at the encoded word.

3
Feed-forward: think it over

A small calculation applied to each position on its own, to digest what attention gathered.

CODE · src/model/transformer.py 
            attn_out = self.self_attn(self.ln1(x), mask=mask, kv_cache=self_attn_cache, first_loop=i == 0)            x = self.res1(attn_out, x)
PLAIN ENGLISH

Tidy the notes (ln1 rescales them), then run self-attention on them. The mask says which positions may be looked at.

Add the result on top of the notes we started with, so nothing learned earlier is thrown away.

💡
Add, don't replace

That second line is a residual connection: each stage adds its contribution to the running notes. It is what lets deep stacks of layers train at all, and you will find the same pattern in almost every modern neural network.

Predicting the next token

During training the writer is shown the true answer and asked, at every position, "what comes next?". Take the answer −1216. That is five separate predictions, made in one pass:

<eos> must predict <ans> (the answer starts here)
<eos> <ans> must predict INT- (the sign)
<eos> <ans> INT- must predict 1 (the thousands chunk)
<eos> <ans> INT- 1 must predict 216 (the last chunk)
<eos> <ans> INT- 1 216 must predict <eos> (the answer is finished, stop writing)

The middle three predictions are the number itself. A mask stops each position from peeking at the tokens to its right, so the writer cannot copy the answer. When the model is tested, the true answer is hidden: it writes one token at a time, feeds each one back in, and stops when it produces <eos>.

PLAIN ENGLISH

If the model has both a reader and a writer:

Let the reader encode the word. It returns its notes and a map of which positions are real rather than padding.

The writer's input is the answer with its last token removed.

Run the writer. It returns logits: a score for each of the 1,012 tokens, at every position.

The correct answers are the same sequence with its first token removed.

A few lines later the scores are compared with the targets to give one number, the loss:

CODE · src/model/base.py 
        loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1), ignore_index=self.pad_index)
PLAIN ENGLISH

Measure how much score the model put on the wrong tokens, averaged over the batch. ignore_index=self.pad_index is the promise from Module 3: padding positions are left out.

Nudging the sliders

Once the Trainer has the loss, it runs the same few lines after every batch.

CODE · src/trainer.py 
        self.scaler.scale(loss).backward()         if self.params.clip_grad_norm > 0:            self.scaler.unscale_(self.optimizer)            clip_grad_norm_(_unwrap_model(self.model).parameters(), self.params.clip_grad_norm)         self.scaler.step(self.optimizer)        self.scaler.update()        self.optimizer.zero_grad(set_to_none=True)
PLAIN ENGLISH

Work out, for every slider, which direction would have reduced the loss. That set of directions is the gradient.

If a limit is set (the default is 5), shrink any oversized nudge so one odd batch cannot wreck the model.

Move every slider a small step. The optimizer decides exactly how far.

Housekeeping for an optional speed mode.

Wipe the directions clean, ready for the next batch.

How far "a small step" goes is set by the learning rate. Here it is written inside the optimizer setting: adam,lr=0.0001.

The settings that shape the model

These are the flags you are most likely to change, with their defaults from train.py.

--n_enc_layers 4 How many layers the reader has. --n_dec_layers does the same for the writer.
--enc_emb_dim 256 How many numbers of notes each position carries. Wider notes mean many more parameters.
--n_enc_heads 8 How many separate "looks" attention takes at once. enc_emb_dim must be a multiple of this (each head gets an equal slice: 256 / 8 = 32 numbers).
--batch_size 32 How many examples are processed per step.
--optimizer adam,lr=0.0001 The update rule and its learning rate.
--model_type transformer Can also be lstm or gru, two older designs kept for comparison.
🧭
The shipped run is smaller than the defaults

It used 2 layers on each side and a width of 200. The notebook examples go smaller still (1 or 2 layers, width 128) so they finish in minutes on a laptop.

05

Scoring, saving and debugging

How an answer is graded, what the real numbers say, how a run survives a crash, and what to check when training misbehaves.

Marking with partial credit

A good maths teacher does not only write "wrong". They note whether the size of the answer was right and only the sign slipped. This project grades the same way.

At evaluation time the model writes its answer alone, token by token, until it produces <eos>. The tokens are turned back into an integer and passed to this function.

CODE · src/envs/generators/amplitudes.py 
    def evaluate(self, problem, question, answer, hyp, metrics):        if hyp is None:            return {"is_valid": -1}        if hyp == answer:            return {"is_valid": 1, "correct_sign":1, "correct_module": 1}        same_sign = (hyp * answer > 0)        same_module = (abs(hyp) == abs(answer))        res = {"is_valid": 0}        res["correct_sign"]= 1 if same_sign else 0        res["correct_module"]= 1 if same_module else 0        return res
PLAIN ENGLISH

Grade one prediction (hyp, short for hypothesis) against the true answer.

If the model's tokens could not be read as a number at all, mark it malformed (-1).

If it matches exactly, full marks on everything.

Otherwise: do the two numbers have the same sign? (Their product is positive only if they do.)

Do they have the same size once the sign is ignored?

Record it as wrong overall...

...but note separately whether the sign was right...

...and whether the size was right.

Hand the marks back.

When training misbehaves

Four symptoms cover most bad runs. The first two come with the author's own notes from the notebook.

📉

Training loss falls, test loss rises

The model is memorising. This is overfitting. The notebook sees it with 5,000 examples and almost none with 20,000.

🪨

Loss never comes down

Suspect the learning rate first. The notebook notes that 0.01 does not learn and 0.001 does.

🛑

Stops at once with AssertionError

A sanity check failed before training: a missing file, a width that does not divide by the heads, or a task name that does not match.

🔁

A "new" run resumes an old one

The experiment folder already held a checkpoint.pth, so the Trainer reloaded it. Use a fresh --exp_id.

⚠️
Two easy mistakes with the data flags

The files in data/ ship zipped and the loader reads plain text, so they must be unzipped first (the notebook's first cell does this). And reload_data needs the task name in front: amplitude:../data/5.train, not just the path.
