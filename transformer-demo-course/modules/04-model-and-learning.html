04

The model and one learning step

What is inside the transformer, how it is told it was wrong, and which settings change its size.

A mixing desk with 2.8 million sliders

Picture a sound engineer at a mixing desk. The sound that comes out depends entirely on where the sliders sit. Training is the engineer listening, then nudging every slider a tiny amount towards a better sound.

The model's sliders are called parameters. The shipped run logs Number of parameters: 2856000.

👓

Encoder: the reader

Reads all the letters of the word at once and produces a set of internal notes about it.

✍️

Decoder: the writer

Writes the answer one token at a time, consulting the reader's notes before each token.

This two-part design is the default, encoder_decoder. The --architecture flag also accepts encoder_only and decoder_only.

What one layer does

The reader and the writer are each a stack of identical layers. Every layer runs the same short routine.

1
Self-attention: look at your neighbours

Each position looks at every other position in its own sequence and decides which ones matter for it.

2
Cross-attention: look at the reader's notes

Writer layers only. Each answer position looks back at the encoded word.

3
Feed-forward: think it over

A small calculation applied to each position on its own, to digest what attention gathered.

CODE · src/model/transformer.py 
            attn_out = self.self_attn(self.ln1(x), mask=mask, kv_cache=self_attn_cache, first_loop=i == 0)            x = self.res1(attn_out, x)
PLAIN ENGLISH

Tidy the notes (ln1 rescales them), then run self-attention on them. The mask says which positions may be looked at.

Add the result on top of the notes we started with, so nothing learned earlier is thrown away.

💡
Add, don't replace

That second line is a residual connection: each stage adds its contribution to the running notes. It is what lets deep stacks of layers train at all, and you will find the same pattern in almost every modern neural network.

Predicting the next token

During training the writer is shown the true answer and asked, at every position, "what comes next?". Take the answer −1216. That is five separate predictions, made in one pass:

<eos> must predict <ans> (the answer starts here)
<eos> <ans> must predict INT- (the sign)
<eos> <ans> INT- must predict 1 (the thousands chunk)
<eos> <ans> INT- 1 must predict 216 (the last chunk)
<eos> <ans> INT- 1 216 must predict <eos> (the answer is finished, stop writing)

The middle three predictions are the number itself. A mask stops each position from peeking at the tokens to its right, so the writer cannot copy the answer. When the model is tested, the true answer is hidden: it writes one token at a time, feeds each one back in, and stops when it produces <eos>.

PLAIN ENGLISH

If the model has both a reader and a writer:

Let the reader encode the word. It returns its notes and a map of which positions are real rather than padding.

The writer's input is the answer with its last token removed.

Run the writer. It returns logits: a score for each of the 1,012 tokens, at every position.

The correct answers are the same sequence with its first token removed.

A few lines later the scores are compared with the targets to give one number, the loss:

CODE · src/model/base.py 
        loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1), ignore_index=self.pad_index)
PLAIN ENGLISH

Measure how much score the model put on the wrong tokens, averaged over the batch. ignore_index=self.pad_index is the promise from Module 3: padding positions are left out.

Nudging the sliders

Once the Trainer has the loss, it runs the same few lines after every batch.

CODE · src/trainer.py 
        self.scaler.scale(loss).backward()         if self.params.clip_grad_norm > 0:            self.scaler.unscale_(self.optimizer)            clip_grad_norm_(_unwrap_model(self.model).parameters(), self.params.clip_grad_norm)         self.scaler.step(self.optimizer)        self.scaler.update()        self.optimizer.zero_grad(set_to_none=True)
PLAIN ENGLISH

Work out, for every slider, which direction would have reduced the loss. That set of directions is the gradient.

If a limit is set (the default is 5), shrink any oversized nudge so one odd batch cannot wreck the model.

Move every slider a small step. The optimizer decides exactly how far.

Housekeeping for an optional speed mode.

Wipe the directions clean, ready for the next batch.

How far "a small step" goes is set by the learning rate. Here it is written inside the optimizer setting: adam,lr=0.0001.

The settings that shape the model

These are the flags you are most likely to change, with their defaults from train.py.

--n_enc_layers 4 How many layers the reader has. --n_dec_layers does the same for the writer.
--enc_emb_dim 256 How many numbers of notes each position carries. Wider notes mean many more parameters.
--n_enc_heads 8 How many separate "looks" attention takes at once. enc_emb_dim must be a multiple of this (each head gets an equal slice: 256 / 8 = 32 numbers).
--batch_size 32 How many examples are processed per step.
--optimizer adam,lr=0.0001 The update rule and its learning rate.
--model_type transformer Can also be lstm or gru, two older designs kept for comparison.
🧭
The shipped run is smaller than the defaults

It used 2 layers on each side and a width of 200. The notebook examples go smaller still (1 or 2 layers, width 128) so they finish in minutes on a laptop.
