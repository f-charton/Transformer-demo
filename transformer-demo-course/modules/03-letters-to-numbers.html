From letters to numbers

A model can only do arithmetic. Follow one line of the data file as it is turned into something the model can read.

The codebook

A telegraph operator cannot send the word "storm". They look each letter up in a codebook and send the code. The receiver uses the same codebook to turn it back.

The project does the same thing in two steps. First it cuts the text into pieces called tokens. Then it replaces each token with its line number in a list called the vocabulary.

How an integer becomes tokens

The letters are easy: one letter, one token. The answer needs a decision. The code writes the sign as its own token, then cuts the digits into chunks using a number base of 1000.

CODE · src/envs/tokenizers/integer.py 
    def encode(self, value):        value = int(value)        base = self.base        neg = value < 0        value = -value if neg else value        res = []        while True:            rem = value % base            value = value // base            res.append(str(rem))            if value == 0:                break        tag = "INT-" if neg else "INT+"        return [tag] + res[::-1]
PLAIN ENGLISH

A recipe named "encode" that takes one number.

Make sure it is a whole number.

Look up the base (1000 by default).

Remember whether the number is negative, then drop the minus sign.

Start an empty list of chunks.

Repeat: peel off the last three digits (the remainder after dividing by 1000) and keep what is left.

Store the chunk as text.

Stop once nothing is left.

Pick the sign token.

Hand back the sign followed by the chunks, biggest first.

288 becomes INT+ 288 (two tokens)
-16 becomes INT- 16 (two tokens)
-1216 becomes INT- 1 216 (three tokens)

Building the vocabulary

When the Environment is created, it collects every token the task could ever use and numbers them. This list is fixed before training starts.

🏷️

4 special tokens

<eos> end of sequence, <pad> filler, <query>, and <ans> "answer starts here". IDs 0 to 3.

🔢

1,002 answer tokens

The chunks 0 to 999, plus INT+ and INT-.

🔤

6 letters

a to f, which land at IDs 1006 to 1011.

That makes a vocabulary of 1,012 tokens. The model's first and last layers are sized to exactly this number.

Why batches need padding

The model processes a batch as a rectangular grid, so every row must have the same length. Answers have different lengths, so shorter rows are filled with <pad>.

<eos> <ans> INT- 1 216 <eos> The answer -1216, six positions
<eos> <ans> INT+ 288 <eos> <pad> The answer 288, one filler added to match

Notice that <eos> appears at both ends. This code uses the same token to mark the start and the end of a sequence.

🧭
Padding must not count

Filler positions carry no information, so the model must be neither rewarded nor punished for them. Module 4 shows the one line that tells the scoring to ignore the pad ID. Forgetting this is a classic bug in sequence models.
