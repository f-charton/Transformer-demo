Meet the cast

Six pieces of code do all the work. Knowing who does what tells you where any change belongs.

A sports club, not one big program

The code is organised like a small sports club. Each role has one job, and the manager only decides who goes next.

📋
train.py: the club manager

Reads the settings, hires everyone, then calls "train" and "evaluate" in turn.

📖
Environment: the rulebook

Knows the task: which symbols exist, how to write an answer, how to judge one.

🧺
EnvDataset: the kit manager

Hands out the drills: reads cards from a file and packs them into small groups.

🏃
Model: the athlete

The transformer. It is the only piece that actually learns.

📣
Trainer: the coach

Runs each practice step, corrects the athlete, and keeps the save files.

⚖️
Evaluator: the referee

Sets the exam on held-back cards and reports the scores. Never corrects the athlete.

Where each one lives

Every role has its own file. The src/ folder is a package that train.py borrows from.

train.py The manager. Start reading here.
src/ Everything the manager calls
trainer.py The coach
evaluator.py The referee
dataset.py The kit manager
model/ The athlete: transformer.py, plus an older-style alternative in rnn.py
envs/ The rulebook, with one small file per task in ops/
optim.py, utils.py, logger.py, slurm.py Support staff: the optimiser, the experiment folder, the log, multi-machine runs
data/ The flashcard decks, zipped
notebooks/ Base.ipynb, the friendly way to launch runs

The hiring, line by line

This is the moment in train.py where the manager builds the team. The order matters: each new hire is handed the ones before it.

A note to human readers; the computer ignores it.

Write the rulebook for the chosen task. It comes first because it decides how many symbols exist.

Work out whether an optional speed-up is wanted and possible.

Build the athlete, sized according to the settings and the rulebook.

The author's own warning: the speed-up did not help when they tried it.

Apply the speed-up only if it was asked for.

Hire the coach and hand over the athlete, the rulebook and the settings.

Hire the referee and hand over the coach, so the referee can reach everything the coach holds.

💡
Separation of concerns

Giving each piece one job is called separation of concerns. It is why you can swap the task without touching the model, or change the model without touching the scoring. When you ask an AI assistant for a change, name the piece: "change how answers are scored in the generator's evaluate function" gets a far better result than "fix the accuracy".
